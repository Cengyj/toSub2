# 2FA 重置及一次性退出：实现与验证记录

## 使用方式

- 尚未启用 2FA 的账号使用“设置 2FA”。已有 2FA 的账号使用独立的“重置 2FA”；原设置按钮不会强行解禁。
- 单个账号的“设置 2FA / 重置 2FA”位于账号名下方，避免宽表格的右侧操作列被横向滚动遮住。批量操作先勾选账号，再用“批量重置 2FA”，不符合条件的账号跳过。
- 点击单个或批量设置/重置后，确认窗口直接提供“成功后退出所有设备（仅本次）”复选框。每次打开默认不勾选；取消、关闭和完成后均不保留选择，只有点击确认才提交。
- 重置确认框说明旧验证器密钥会失效，以及移除和新建之间可能出现未完成状态。退出选项说明密钥激活并保存后只请求一次，不巡检、不自动重试，包含当前网页登录。
- 每个账号名下方新增“查看资料”和“导出账号资料”；批量工具栏使用“批量导出账号资料”。原 OAuth 下载明确命名为“下载授权文件”，避免与登录资料混淆。
- 资料弹窗按需读取邮箱、当前保存的密码、2FA 密钥与邮箱收码信息。密码、密钥和收码信息默认遮盖，可单独显示或复制；关闭时清空，账号状态/版本变化或刷新时旧内容立即失效。不会将这些资料加入任务轮询或浏览器存储。
- 导出每次重新读取服务端当前凭据，不复用弹窗快照；设置/重置完整成功后导出新密钥。保留原有 UTF-8 BOM 文本和四横线导入格式。密码或 2FA 正在修改、恢复未完成或旧密钥已失效时拒绝查看/导出，避免把旧密钥误作当前密钥。
- 退出结果分别显示请求成功、失败、未知或未执行。退出失败不会让程序重新移除或重新创建 2FA。

如果用户已经在浏览器中手动更换了 2FA，本地保存的旧密钥不会自动变成新密钥；下一次登录需要当前有效的认证信息。本次实现不会自动将 HAR 中的 secret 导入真实账号凭据。

资料读取按平台区分：Windows / macOS 从系统安全凭据存储读取，读取失败不会回退到历史任务里的秘密值；Linux 等不支持持久凭据存储的平台，仅使用本次服务会话中已接受的凭据，重启后需重新导入。同邮箱的历史任务不会覆盖较新的会话凭据。此兼容处理不会把内存保存当作 2FA 安全持久化成功，也不会解除恢复或失效密钥保护。

## 实际接入

- `web/src/main.jsx` / `styles.css`：重置入口、首次设置禁用原因、仅本次退出选项、选择数量、确认及结果提示，操作按钮自动换行。
- `src/console-server.mjs`：单个和批量已有 setup 路由接收严格布尔字段 `resetTotp` 与 `logoutAllDevicesAfterTotp`，默认均为 false；同账号互斥、runId 关联、持久化 ACK、读回验证和恢复状态。
- `src/protocol-login.mjs`：显式重置依次读取当前因子、移除、查询确认、创建、激活、查询新因子；重置操作必须具备父进程保存确认通道。未提供该通道时，在任何账号请求之前停止。
- `src/tls-transport.mjs` / `src/tls_transport.py`：单次请求关闭应用重试、风控求解、重定向跟随与重放；支持独立默认头控制及真实删除头。Python 对单次请求使用新连接并禁止复用，消除本地实测中连接断开导致的 libcurl 内部重发。

所有账号 ID、设备 ID、因子 ID、session ID、secret 与验证码均来自当前流程，不从捕获文件硬编码。原始抓包和账号请求审计材料属于本地资料，不随公开仓库发布。协议请求形态与错误处理由下方的模拟服务测试验证。

## 持久化与中断处理

1. 发送移除前将意图写入私有文件，并等待父进程验证系统凭据存储可用、保存阶段元数据。旧加密密钥暂留作恢复记录，不再作为当前有效凭据自动使用。
2. 移除或退出开始前删除旧登录检查点。服务恢复不会重放已经记录过的安全修改。
3. 激活接口返回成功时立即写入 `activation_succeeded`；后续 MFA 查询验证单独写入 `activation_verified`。查询失败不能抹掉“激活已成功”的事实。
4. 只有验证新因子并将新密钥安全保存、读回一致后，重置才算完整成功；此时才允许用户选择的退出请求。
5. 结果不明确或保存失败时保留私有恢复资料、标记需要核实，并阻断可能覆盖恢复文件或使用旧密钥的自动流程。恢复资料的清理发生在凭据和元数据可靠保存之后。
6. “激活已成功、后续查询失败”的新密钥可以加密备份，但任务仍显示未完成，不会自动退出或重新移除；对恢复资料和自动登录的保护不会因为备份成功就解除。

没有增加巡检、定时退出、失败自动补发或启动自动续跑。现有号池监控调度未被扩展为本功能的执行器。

## 验证边界

上述网络测试使用虚构账号和本机回环服务，DPAPI 使用隔离临时目录，不操作用户真实账号。它们证明当前程序的流程、发包形态和中断保护，不代表已经对 ChatGPT 真实环境执行移除、重新激活或验证所有真实设备都退出。真实服务可能返回额外身份验证或风控响应；程序会显式停止并呈现结果，不绕过验证。

真实请求头保持当前传输环境一致，未复制 HAR 的固定账号/设备 ID 或捕获浏览器的客户端专用标记，也未把不匹配的 UA 强行套在不同版本的 TLS 配置上。模拟测试验证程序的请求行为，不能代替真实服务当前可用性的验证。
